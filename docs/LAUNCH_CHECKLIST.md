# 公開前チェックリスト・運用設計

このLPは「実装済み」と「運用側で決める必要があること」を分けています。下記の未チェック項目は、コードでは解決できない（または未確定の）事項です。

## 0. 相談担当者の公開プロフィール（`src/config/counselors.ts`）

LPでは相談担当者の実名・勤務先を出さず、経験とバックグラウンドで信頼をつくる方針です。現在は全項目が未入力で、画面上は「【公開前に入力】」表示になっています。

- [ ] ニックネーム（担当者名）
- [ ] 相談に向き合う姿勢
- [ ] 実際のバックグラウンド（事実のみ。勤務先・所属名は書かない）
- [ ] 経験・問題意識
- [ ] 得意な相談テーマ
- [ ] 対応範囲と限界
- [ ] 資格・研修歴（任意。証明書等で確認できたもののみ）
- [ ] LPに「経歴や資格は、事実として確認できたものだけを掲載します」と書いているため、確認方法と記録を残す
- [ ] 公開までに入力が間に合わない場合は `COUNSELOR_SECTION_VISIBLE = false` にしてセクションごと非表示にする（ヘッダー・FAQのリンクも消える）
- [ ] 担当者が従業員以外の場合の契約形態・守秘義務（プライバシーポリシー 4-2 のプレースホルダー）

- [ ] 有料サービスを始める場合は、特定商取引法に基づく表記（事業者名・代表者・所在地・連絡先等）が必要になるため、事業者情報の未入力項目を必ず埋める

## 2. メール

件名に悩みの内容を入れないこと（通知やロック画面で見られる可能性があるため）。

- 予約確認メール：件名「His Recoveries｜ご予約について」
  - 予約日時／Google Meet 参加URL／変更・キャンセル方法／問い合わせ先／AI記録の事前説明（利用する場合）
- 相談後のまとめメール：件名「His Recoveries｜対話のまとめ」
  - 本文の冒頭は「対話のまとめをお送りします」程度にとどめ、プレビューに悩みの具体的な内容が出ないようにする
  - 送信前に宛先が予約時のメールアドレスと一致することを確認（誤送信防止）
- [ ] TimeRex の通知メール件名を上記に変更できるか確認。LPに「件名には相談テーマなどの内容を入れない運用にします」と書いているので、実際の件名・本文プレビューで確認する
- [ ] 送信元メールアドレス・表示名が担当者の実名にならないよう設定する
- [ ] 問い合わせ用メールアドレスを決め、`CONTACT_EMAIL` に設定

## 3. AIによる記録・要約の運用

LP・ポリシーでは次のことを約束しています。運用がこれと一致するまで、AI記録は開始しないでください。

- [ ] 利用するツールの決定（録音／文字起こし／AI要約のどれを、どのサービスで行うか）。Google Meet の録画・文字起こし機能を使う場合、その旨を明示する（LPでは「録画なし」とは表示していません）
- [ ] 事前説明文の作成：何を記録するか／どのサービスを使うか／目的／保存先／保存期間／削除方法
- [ ] 同意の取得方法：予約時または予約確認メール後の同意＋**相談開始時に口頭で再確認**
- [ ] 同意しない場合の相談手順（記録ツールを起動しない）
- [ ] 同意撤回時の手順（記録停止・削除）
- [ ] AIサービスに入力したデータが学習に使われない設定・契約であることの確認
- [ ] AIが作成したまとめを担当者が確認・修正してから送る手順
- [ ] AIに医療的な診断をさせないプロンプト・運用ルール
- [ ] データの保存場所・アクセス権限・保存期間・削除手順の決定
